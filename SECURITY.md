# Sicherheitsrichtlinie

## Zweck und Geltungsbereich

Dieses Repository enthält Dokumentations- und Prüfarbeitsmittel, aber keine produktive KI-Laufzeit. Sicherheitsrelevant sind insbesondere Fehler, die organisationsspezifische Inhalte veröffentlichen, Schutzstatus-Gates umgehen, lokale Eingaben in Git aufnehmen, Quellen oder Nachweise verfälschen oder erzeugte Artefakte manipulieren können.

## Vertrauliche Meldung

Sensible Schwachstellen dürfen nicht als gewöhnliches GitHub-Issue eingestellt werden. Sofern die Funktion im Repository aktiviert ist, ist unter **Security → Report a vulnerability** eine private Meldung zu erstellen. Ist diese Funktion nicht verfügbar, muss zunächst über einen bereits bekannten, autorisierten privaten Kommunikationsweg Kontakt mit dem Repository-Verantwortlichen aufgenommen werden. Es wird bewusst keine nicht bestätigte Kontaktadresse angegeben.

Eine Meldung sollte betroffene Revision, reproduzierbare Schritte, Auswirkung und eine möglichst datensparsame Nachweisdarstellung enthalten. Reale Geheimnisse, personenbezogene Daten und interne Infrastrukturangaben sind nicht beizufügen.

## Erwarteter Ablauf

Der Eingang wird geprüft, der Umfang eingegrenzt und eine koordinierte Behebung vorbereitet. Veröffentlichung und technische Einzelheiten werden erst nach Abstimmung und angemessener Behebungsmöglichkeit behandelt. Zeitliche Garantien werden nicht gegeben.

## Responsible Disclosure

Bitte keine aktive Prüfung gegen Systeme, Konten oder Infrastrukturen Dritter durchführen. Eine Meldung begründet keine Berechtigung zu Zugriffen oder zur Verarbeitung fremder Daten. Gutgläubige, datensparsame und koordinierte Meldungen werden sachlich behandelt.

## Grenzen

Die Referenzvorlage ist keine Sicherheitsgarantie, Zertifizierung, Akkreditierung oder Freigabe eines konkreten Systems. Organisationsspezifische Umsetzungen benötigen eine eigene Risikoanalyse, Nachweise und befugte Freigaben.
